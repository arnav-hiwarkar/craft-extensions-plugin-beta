<section id="status" aria-labelledby="status-h">
<h2 id="status-h">Status and decisions</h2>
<div class="callout"><p>Jeremy&#x27;s direction, 16/10/2026: while the AI infrastructure is being sorted, start the plan for a shared plug-in, theme and extension browser that is native to ArtCraft Launcher and reachable from each app. Then, same day: start with internal (first-party) extensions, but build the structure for third party that requires heavy security gates. Third party stays switched off until every gate passes. Then: build Phase 1 end to end (threat model, core and store crates, launcher Themes screen, PhotoCraft theme adapter, into his test build), crates in a standalone workspace, and a public repo for it (created on his GitHub as Jeremy8776/craft-extensions on 16/10/2026, first commit 5500b37, CI green; moved to storytold/craft-extensions on 04/11/2026). Built so far (pushed to that repo as 33adcb4, CI green on Linux and Windows): craft-ext-core and craft-ext-store with tests and mutation checks. The launcher Extensions screen (Themes and Installed tabs) is built and tested in the craft-launcher-ext worktree with a debug build at craft-launcher-ext/target/dev. The launcher work is on branch feat/extensions (70b9612) in Jeremy8776/craft-launcher, a fork made 16/10/2026 because storytold/craft-launcher is read-only for him. The PhotoCraft adapter is on feat/extensions-theme-adapter (ecb056cc) in Jeremy8776/photocraft. No pull request has been opened. Jeremy has reviewed the launcher TEST BUILD UI; PhotoCraft remains a separate verification gate. 16/10/2026 follow-up: the launcher UI polish stays in the throwaway test branch until the real plug-in infrastructure and PhotoCraft host work end to end. Then extract it cleanly, verify a fresh checkout and hand off source PRs plus a versioned installer candidate. The example plug-ins are demo data, not shipped packages. Nothing is pushed or published by this plan.</p></div>

<section id="tiers" aria-labelledby="tiers-h">
<h2 id="tiers-h">Trust tiers: internal on, third party built but off</h2>
<p>Third party is designed in from the first schema so it never needs a rewrite, but nothing outside the storytold organisation can be installed until every gate in phase 3 passes.</p>
<div class="scroll"><table>
<caption>Tiers</caption>
<thead><tr>
<th scope="col">Tier</th>
<th scope="col">Who</th>
<th scope="col">How it is checked</th>
<th scope="col">State</th>
</tr></thead><tbody>
<tr><th scope="row">Made by ArtCraft</th><td>storytold, built and released by the organisation</td><td>Hash pinned in the index; downloaded only from storytold releases</td><td>On</td></tr>
<tr><th scope="row">Added from a file</th><td>The person&#x27;s own file</td><td>Bounded unpack and validators; the sandbox still applies; clear warning in plain words</td><td>On</td></tr>
<tr><th scope="row">Reviewed third party</th><td>An outside publisher</td><td>Publisher signature, pinned key, fresh signed index, revocation, reserved namespaces, review of the index entry, provenance</td><td>Off: compiled out of release builds and refused at run time until gate sg13</td></tr>

<section id="requirements" aria-labelledby="requirements-h">
<h2 id="requirements-h">Requirements the shared layer must meet</h2>
<div class="scroll"><table>
<caption>Requirements</caption>
<thead><tr>
<th scope="col">ID</th>
<th scope="col">Requirement</th>
</tr></thead><tbody>
<tr><th scope="row" id="req-q1">q1</th><td>Install once, enable per app. Installing in one place makes the extension available to every compatible app.</td></tr>
<tr><th scope="row" id="req-q2">q2</th><td>An app with no launcher still works: it can install from a file and manage what it has, using the same store.</td></tr>
<tr><th scope="row" id="req-q3">q3</th><td>A running app notices an install or a switch without a restart and without IPC.</td></tr>
<tr><th scope="row" id="req-q4">q4</th><td>Every package is hostile input: bounded unpack, no path escape, size and count caps, hashes checked before use. Nothing panics.</td></tr>
<tr><th scope="row" id="req-q5">q5</th><td>Themes carry no code. Plug-ins have no ambient authority (no files, network, clock) in version 1; the permissions field must be empty, for every tier.</td></tr>
<tr><th scope="row" id="req-q6">q6</th><td>One theme file works in every app: a small shared palette, per-app overrides optional, unknown apps ignored.</td></tr>
<tr><th scope="row" id="req-q7">q7</th><td>Anything a person reads is plain language, enforced by a test. No ABI, wasm, sandbox or adapter in visible strings.</td></tr>
<tr><th scope="row" id="req-q8">q8</th><td>The contract and store core build for wasm32-unknown-unknown; file and process code is cfg-gated.</td></tr>
<tr><th scope="row" id="req-q9">q9</th><td>Each host draws its own view: launcher look in the launcher, the app&#x27;s theme inside an app. Shared code owns data and a neutral fallback only.</td></tr>
<tr><th scope="row" id="req-q10">q10</th><td>First-party entries pin a SHA-256 and come only from storytold releases. The page says plainly that hash pinning does not prove who made a file.</td></tr>
<tr><th scope="row" id="req-q11">q11</th><td>Launcher strings go through tl! into the four catalogs. Extension names and descriptions are third-party data and stay untranslated.</td></tr>
<tr><th scope="row" id="req-q12">q12</th><td>The third-party path exists in the schema and the code but is off: behind a cargo feature that release builds never enable, refused at run time, and guarded by a test that fails if it is enabled.</td></tr>
<tr><th scope="row" id="req-q13">q13</th><td>Third-party trust needs a publisher signature, a pinned key, a fresh signed index (expiry, no rollback), a revocation list and reserved first-party namespaces. A revoked package turns off in every app.</td></tr>
<tr><th scope="row" id="req-q14">q14</th><td>No silent change for third party: a new key, wider permission or downgrade needs a fresh yes; updates never apply on their own.</td></tr>
</tbody></table></div>
</section>

<h3 id="checklist-h">Adapter checklist every app follows</h3>
<ol><li>Map the shared palette to the app&#x27;s own Tokens, derive the rest, then apply [app.&lt;id&gt;] overrides.</li><li>Re-scan the store when the generation counter changes; fall back to the built-in theme if the active one is gone or fails validation.</li><li>Themes &amp; Extensions panel: installed for this app, enable, disable, remove, install from file.</li><li>A &quot;Browse more&quot; button that opens the launcher at this app&#x27;s filter; if the launcher is missing, open its download page.</li><li>Commands (extension.list, extension.enable, theme.set, extension.open_browser) so scripts and agents can drive it.</li><li>Plug-in host only if the app has a plug-in kind; resource importers listed with their formats.</li><li>Strings through the app&#x27;s i18n; a test that scans visible strings for developer words.</li></ol>
