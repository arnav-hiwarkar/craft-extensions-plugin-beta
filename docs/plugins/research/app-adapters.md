# App adapter responsibilities

> **Status (2026-11-10):** history and evidence. The current design is [the Craft plugin architecture](../architecture.md); where this document disagrees with it, the architecture wins.

Status: proposed adapter reference, 2026-11-08. Observed foundations below come from the [primary source investigation](../../plugin-functional-primary.md) and its [16-app inventory](../../plugin-functional-inventory.json). They are revision-bound source observations, not runtime acceptance. The matrix does not promise a generic plugin host already exists in every app.

## Checklist shared by every adapter

Every app integration must provide the following responsibilities. They may live in existing app modules; this is not a demand for one new module per row.

| Responsibility | Shared input | App-owned output and acceptance fixture |
|---|---|---|
| Discovery | Store metadata and generation, source/package/contribution identities | Namespaced commands/features without executing discovery callbacks |
| Compatibility | App version, contracts, engine profile, target and required backend/resources | Precise supported/unsupported/pending status per contribution |
| Activation | Enabled preference, grants, build policy, revocations and quarantine | Same resolver result at GUI, CLI, enable, reopen and load |
| Runtime loading | Exact retained manifest and verified module bytes | Actual engine applies declared import/feature limits before instantiation |
| Contributions and UI | Versioned operation/parameter/panel descriptions | Native controls, localization, accessibility and disposable callbacks |
| Validated commands | Host-created instance identity and scoped authority | Parameter-aware capability enforcement including nested operations |
| Transactions | Proposed edits, captured document revision and bounded results | Commit/undo/redo; trap, cancellation and stale result leave no partial edit |
| Persistence | Contribution reference, release identity, parameters and state schema | Save/reopen, unknown-state preservation, explicit migration and missing-feature handling |
| Job ownership | Pinned releases/resources, budgets, progress and cancellation | No deleted lazy inputs; truthful terminal state and no orphan one-shot CLI work |
| CLI bootstrap | Fresh/attached/server session mode and selected store | Installed eligibility without new grants/downloads, explicit targets and output |
| Artifacts | Typed output descriptor and caller-selected destination | Host writes/commits result; no hidden save dialog or silent output loss |
| Errors and recovery | Structured reason, job/release identity and redaction policy | Useful failure, safe startup and app-specific quarantine |
| Theme mapping | ThemeFile palette and allowlisted app overrides | Contrast/status/selection fixtures and fallback; WidgetPalette stays a drawing API |
| Conformance | Real package and literal expected app results | GUI/CLI parity, denied calls, cancellation and lifecycle failures at candidate revision |

## Concrete integration matrix

Each row inherits the entire checklist above. The last column identifies the app-specific fixture needed in addition. “Candidate” describes future scope, not observed support. Source revisions are recorded in the linked inventory; deeper evidence links follow the table.

| App | Observed foundation | Contract and document ownership | Jobs, CLI, artifacts and theme semantics | Additional acceptance fixture |
|---|---|---|---|---|
| EffectCraft | WASM effects and helper protocol, effect registry, separate desktop/CLI startup paths | Preserve effects ABI through an adapter; layer instance parameters, keyframes, frame/time requests and independent temporal state | Render job pins releases/resources; fresh CLI resolves installed effects; export must reject required unresolved effects; graph/keyframe/status colours remain app-owned | Two layer instances, seek/reset, concurrent preview/export and missing-effect final export |
| FigCraft | WASM commands and panel callbacks, widgets and document transactions | Command/query allowlist, selection handles, declarative panels and optional persistent widgets; no blanket command-bus permission | Menu/panel/CLI share operation; headless output descriptor replaces save dialog; transaction commits belong to engine; selection and canvas meaning preserved | Same command produces literal native objects through panel and CLI; denied nested write; panel disposal and undo |
| PhotoCraft | WASM surface-band filters; separate shared-theme adapter branch | Colour mode, alpha, selection blending, overlap, preview and destructive/live state remain app-owned | PhotoCraft filter job holds input/output bounds; CLI readiness needs verification; ThemeFile maps to PhotoCraft tokens with contrast and built-in fallback | Existing theme/invert package round trip, selected pixels, band seams, non-RGBA mode and reopen |
| FilmCraft | Command timeline engine and CLI long operations; processing plugin host not established | Start with explicitly supported timeline commands; design timebase, frame/audio dependencies and temporal effects separately | CLI awaits timeline/export jobs; explicit media artifact; timeline clip/track/selection/status colours require independent token mapping | Command undo and completed export; theme selection/status fixture; later temporal boundary and device-loss fixture |
| VectorCraft | Object plugins, live geometry effects and exporters; CLI persisted-store setup | Object/units schema, appearance evaluation, independent live instance state and validated exporter results | Host writes export bytes; invalidate geometry/appearance caches; preserve selection/outline meanings | Object command versus live effect save/reopen; malformed geometry; explicit exported artifact |
| SoundCraft | Native AU/VST3/CLAP family adapters and DSP interface | Dedicated audio prepare/reset/process, channel layout, transport/MIDI, sample offsets, latency/tail, automation and opaque state | Existing native host is not sandbox proof; worker failure and deadline handling need dedicated design; headless bounce and plugin editor are separate | Future bounded-latency/dropout evidence, state restore and worker failure before selecting sandbox runtime |
| LightCraft | Catalog/develop commands and background rendering | Catalog item targets, RAW/develop stages and nondestructive recipe state | Background export owns dependencies and artifact completion; semantic exposure/clipping colours protected | Develop recipe reopen, source media missing and export job cancellation |
| PDFCraft | Open-document facade and automation tool table | Page/object handles, validated edits/history and PDF output; plugin object model not established | Host owns file writes and document lifetime; page/status annotation colours preserved | Page edit undo, stale page handle and completed PDF output |
| DesignCraft | Commands, scripts and journaled pointer tools | Stories/frames/pages/spreads, units, reflow and prepress state | Gesture transaction lifetime differs from one-shot command; export awaits layout; proof/status colours preserved | Cancel a pointer gesture; text reflow undo; explicit prepress output |
| CADCraft | Programmatic commands with interactive prompts | Entity/model units and transactions; headless contracts supply every required prompt parameter | Interactive-only input path is explicit; model saves/export require terminal completion; geometry aids and selection preserved | Missing prompt returns InputRequired; unit-correct edit with rollback and save |
| SolidCraft | Manifest discovery and disabled IDs; parametric runtime is a design | Candidate command adapter first; future parametric features need evaluation/state/fallback contract | Do not expose manifests as evidence of executable support; model jobs and output remain app-owned | An actual command executes transactionally before claiming runtime support; later missing-feature rebuild fixture |
| TextureCraft | Project/mesh/texture-set session, caches, stroke state and command registry | Channels, UVs, mesh targets, bake/composite dependencies and stroke transactions | Pin mesh/textures for bake; explicit output sets; preserve material/selection diagnostic colours | Cancel stroke/bake, wrong texture-set target, cache invalidation after UV edit |
| WordCraft | Command-backed text/document editing | Durable text positions, ranges/styles/stories and layout semantics | Avoid raw offsets surviving edits; jobs await pagination/export; selection and review colours preserved | Concurrent text insertion invalidates stale handles without corrupting document; undo and export |
| GridCraft | Workbook command engine | Cell types/ranges; custom functions need separate recalculation, dependency and error contract | No arbitrary synchronous plugin call on recalculation without budget/cycle rules; output workbook explicit | Typed range edit undo; later custom-function cycle/timeout and deterministic recalc |
| DeckCraft | Presentation command engine and CLI | Slides/shapes/text/transitions and saved state; slideshow callbacks need separate lifecycle | Export awaits jobs; presentation callbacks dispose on stop; slide selection/status preserved | Shape command save/reopen/export; stop callback subscription cleanly |
| ArtCraft | Rust native target and durable provider jobs; plugin host/CLI not established | Candidate provider/model job contract, bounded inputs and media ingestion; account actions separately scoped | Persist generation/result-upload terminal state; no invented common CLI; preserve job/status meaning | Future provider cancellation, restart and result ingestion before claiming an adapter |

## Source anchors and limits

The primary investigation links the inspected definitions for [EffectCraft](https://github.com/arnav-hiwarkar/effectcraft/blob/ce9eaec65015a5508c72af0e2351cd02612c9450/crates/effects/src/plugin.rs), [FigCraft](https://github.com/storytold/figcraft/blob/0e86f3597a7443b15c93ec3ab2091202f8802c95/crates/engine/src/extensions/plugins.rs), [PhotoCraft](https://github.com/storytold/photocraft/blob/655295b2a2c400bded0640f5d97367000a057b2e/crates/plugins/src/apply.rs), [VectorCraft](https://github.com/storytold/vectorcraft/blob/065a646799f1f20f5454845d6648e09a5252c452/crates/plugins/src/effect.rs), and [SoundCraft](https://github.com/storytold/soundcraft/blob/da02c19fcca8fbcc49d66c957e5efcc67a63befe/crates/dsp/src/lib.rs). These are deeper runtime observations. The other apps mostly have entry-point evidence; their rows specify design obligations rather than trace every implementation.

PhotoCraft's theme work is a different revision, [ecb056cc](https://github.com/storytold/photocraft/blob/ecb056cc742848d78f9076893a6b3343e6a75010/crates/ui-egui/src/ext_theme.rs), from its sampled filter runtime. Those branches have not been integrated here. FilmCraft's [preferences](https://github.com/storytold/filmcraft/blob/32749e34f611735460e9773335345db026b7b037/crates/engine/src/settings/prefs.rs) and [CLI](https://github.com/storytold/filmcraft/blob/32749e34f611735460e9773335345db026b7b037/apps/filmcraft-cli/src/main.rs) anchor its source-derived requirements.

Theme support beyond PhotoCraft remains proposed. No row certifies whole-app accessibility, OS confinement, GUI/CLI equivalence or performance. The [app/CLI delegate note](haiku-app-cli-state.md) adds independent edge cases and evidence limits. The [pilot sequence](decisions.md#proposed-validation-order) prioritizes proof without treating the remaining integrations as trivial wiring.
