# 09 · Red-team review of the combined plugin architecture

Date: 2026-11-18. Role: adversarial security review of reports 01–08 taken together. Read-only: no
repository was edited, built or pushed. Source claims marked **[src]** were re-read in this workspace
for this review. Everything else cites the report and section it attacks.

Severity: **Critical** = authority never granted or code outside the sandbox; **High** = a grant exceeded or data leaves without consent; **Medium** = bounded integrity, privacy or availability loss; **Low** = nuisance. Likelihood: **High** = a careless author hits it; **Med** = a motivated attacker or specific setup; **Low** = needs a chain.

---

## 0. Verdict

The reports are individually careful; the holes are at the seams.

1. **03 designs for in-process JIT; 02 forbids it** (C1). 03's zero-copy numbers assume the app
   process, and it rejected the shared-memory route 02 requires.
2. **The bridge checks parameters, not effects** (R1–R4). Commands acting on the live selection, the
   last command or session post-processing slip past the `Id` walker: FigCraft `edit.repeat` reruns
   the previous principal's command **[src] `figcraft/crates/engine/src/session/exec.rs:124,224`**;
   LightCraft writes XMP sidecars after every top-level command **[src]
   `lightcraft/crates/engine/src/lib.rs:630-633`**.
3. **Five permission vocabularies** (C3), and 02's risk function does not cover input filters,
   interception or automation.
4. **Agents are a second way in** (G1–G4): tokenless control ports, loopback grants, synthetic-input
   MCP tools that answer dialogs **[src] `vectorcraft/crates/mcp/src/tools/definitions.rs`**, and plugin
   widgets exposed to `ui.inspect`. Only VectorCraft's legacy install sheet refuses automation **[src]
   `vectorcraft/crates/ui-egui/src/dialogs/plugin.rs:511-520`**.
5. **Auto-run is wider than events** (C8, D1): rendering a document cooks effects, smart filters,
   expression functions, renderers and widgets with document-controlled inputs; 02 D13 covers none.

## 3. Fifteen non-negotiable security invariants (ranked)

Each invariant is stated so that a single deterministic check can fail the build. They resolve the
contradictions in section 1.

| Rank | Invariant | Closes | Proof (CI, fails closed) |
|---|---|---|---|
| 1 | **No plugin-derived machine code runs, or is compiled, in an app process.** Cranelift lives only in `craft-plugin-worker` under the per-OS sandbox. wasmi may run in process. A missed latency target is answered with batching, never with in-process JIT. | C1, C11 | `cargo tree -i cranelift-codegen` empty for app crates; main-app entitlements lack `allow-jit`; `disallowed-methods` bans `wasmtime::Module::new`/`deserialize` outside the worker crate. |
| 2 | **Authority is checked at the sink, with the caller's `Origin` carried through every nesting** (batches, `edit.repeat`, Actions, macros, journal replay, service calls, jobs, post-commit writers). The classification table is a second layer, never the only one. | R3, R4, R6, R7, D5 | Mock sinks that panic on `Origin::Plugin` reached from any exposed command (02 R4); probe that any re-entrant `Session::execute` declares `dispatches`. |
| 3 | **Scope is enforced on what changes, not on what parameters say.** Implicit targets are rewritten to explicit ids, the write-set of every plugin step is ⊆ captured scope ∪ created objects, selection writes are a separate gesture-only permission, and out-of-scope ids are indistinguishable from absent ones. GPU and CPU views are cropped to scope. | R1, R2, R5, P2, C7 | Generated per-command scope test from the lock file (R1); differential error test (R5); masked-view sentinel test (P2). |
| 4 | **Only hardware input can approve trust UI or mint a gesture.** Every input event carries an origin; consent, JIT, install, native and widening sheets ignore automation input; agent-driven clicks run the plugin as principal `agent`. | G3, C9 | Per-sheet test that `answer_dialog`, `press_key`, `ui_click` and `ui.dialog.confirm` cannot change grants. |
| 5 | **No plugin can reach the operator channel.** Every control, MCP and bridge port requires a per-run token that plugin workers and helpers never inherit; loopback grants require a companion challenge and refuse Craft ports; restricted sandboxes deny loopback and Unix sockets. | G1, G2, C6 | Live control-port connect tests from worker, restricted helper and `net.local` grant; environment and fd scan for tokens. |
| 6 | **One closed permission vocabulary and one total risk function.** Every grantable capability is an enum variant with an exhaustive `risk_level` match; input filters, interception, tool replacement and automation are at least L1; fonts system-install and preferences writes have one answer suite-wide. | C3, F1 | Enum-iteration test; grep check that no document or code names a permission the enum cannot parse. |
| 7 | **Automatic execution is capability-free.** Render, cook, expression, renderer, widget and preview contexts, and hooks caused by peer or external-document changes, have no network, secrets, files, clipboard, service or registry writes. Network-dependent results are stored, and re-run only by an explicit user action. | D1, D2, C8 | Contract table test per contribution kind; open-and-render fixture with a panicking network sink. |
| 8 | **Plugin output is untrusted input to the host.** Importer output and plugin edits pass the app's file-parser validation; they cannot create path links, scripts, expressions, foreign `plugin_data` namespaces or external references; primary exports are host-produced and not rewritable. | D3, D6 | Sentinel-link test; importer fuzz targets; export-hash equality test. |
| 9 | **Agents treat all document and plugin text as data, and plugin commands are agent-visible only by opt-in.** Every string from a document, plugin result, panel, log or manifest reaches an agent inside an untrusted envelope; tool descriptions are host templates; disabled or un-opted plugins are absent from every MCP list, generic run tool and Action replay. | G4, C5, R6, D5 | Per-server MCP snapshot tests with injection fixtures; `actions.play` principal test. |
| 10 | **GPU code is a validated package artefact with owner-initialised resources.** No run-time WGSL; identity is validated-IR digest plus package id; strikes are per package; every pooled texture and arena is cleared or owner-tagged before a plugin sees it; no cross-package fusion; no timing to plugins; 02's L1 rules are the floor until the fuzz gate. | C2, P1, P3, P4 | Pool-reuse sentinel test; runtime-pipeline refusal test; per-package quarantine test; fusion-namespace validation test. |
| 11 | **Service calls carry the consumer's authority, not the provider's.** Providers act on handles the consumer passed; the consumer's risk level is the maximum over the providers it may call and is pinned at grant time. | S1, S2 | Cross-scope service edit test; provider-widening hold test. |
| 12 | **Widening is computed on the whole capability surface** (permissions, auto-run kinds, hooks, agent exposure, service exports, shortcuts, apps, risk level) and app-side lock widenings re-surface affected grants; any widening holds the update. | L1 | Manifest-pair table test; lock-diff review-flag test. |
| 13 | **Revocation is bounded in time and complete in reach.** Disable or quarantine stops every execution path (events, render, replay, undo-triggered re-render, service, agents); revocation data older than the freshness budget degrades L2+ Community and native plugins; the kill list is checked at every instantiation. | L2, D5 | Instantiation-counter test after kill; clock-injected freshness test. |
| 14 | **Every plugin-attributable resource is on one per-plugin account, and plugin activity never evicts user state or security evidence.** CPU, RAM, GPU, disk (caches, models, artefacts, `plugin_data`, settings, logs), undo slots, prompts and audit entries are counted; user undo history, the app's own caches and security audit records are never displaced by plugin work. | D4, X1, X3, X4, C12 | Undo-flood test; audit-eviction test; per-store quota test; app-cache invariance test. |
| 15 | **Every host parser reachable by plugin bytes, and every plugin-authored string shown in chrome, is bounded and sanitised.** Fonts, models, SVG, SBS, ICC, LUT, Fluent, presets, worker IPC and GPU command lists each have limits and a fuzz target; names, labels, reasons and log lines refuse bidi and control characters, built-in labels and button words, and are always attributed. The 02 threat→test map gains rows T28+ for every chain in this report. | F2, F3, U1, U2, U3, X2 | Contribution-kind→fuzz-target table test; Unicode refusal fuzz; snapshot tests; threat-map coverage check. |

## 4. Residuals and owner decisions

**Accepted residuals** (state them so nobody "fixes" them by widening): a user who grants
`document.read` plus `network:<host>` consents to that host receiving their work (02 T2); native-full
is total (02 T18), and its consent must say it can drive other Craft apps whose automation ports are on;
GPU driver bugs reachable from valid WGSL; steganography in user-saved exports; peers can always write
bad data into a shared document, so the defence is that nothing runs on it automatically with authority.

| # | Decision | Recommendation |
|---|---|---|
| R-D1 | Cross-process data plane as the baseline (C1)? | Yes; re-measure with pre-faulted shared arenas and record it in 03. |
| R-D2 | Selection as a separate permission (C7)? | Yes, `selection.write`, implied by a gesture on the plugin's own command, refused in background events. |
| R-D3 | Which vocabulary wins (C3)? | `permission.rs` alone: 01's table plus 02's `media.capture` and `net.local`, with 04's hooks as `app.intercept` scopes. Fonts and default settings are user-applied data contributions, not permissions. |
| R-D4 | Loopback for local AI servers (06)? | Only with a companion challenge and the Craft-port refusal of invariant 5. |
| R-D5 | Save veto (C4)? | No. Findings only. |
| R-D6 | Owner of the threat→test map? | The security owner who reviews `api.lock.json` widenings (01 D10). |
